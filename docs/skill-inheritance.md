# Sharing the primary checkout's `.agents` directory

When herdr-projects places a local worktree thread or explicitly restarts one, it prepares the worktree before an agent can start. If the repository's verified primary checkout contains `.agents`, herdr-projects creates one ordinary directory symlink: `worktree/.agents` points to the canonical primary-checkout `.agents` directory. If the source directory is absent, preparation is a no-op. The source must be a real directory inside the standard primary checkout. A symlinked `.agents` source or any symlink entry inside the shared tree is rejected without following it; resolve such entries deliberately inside the primary checkout before retrying.

This shares the entire directory, not just `skills/`. Non-Skill files already there and files or Skills added later are visible through the link without another copy. The link is writable, not a read-only mount: writes through it change the primary checkout. Scripts or other content are never executed by preparation. The resource loader, normal project-trust policy, and its ignore rules decide what the agent discovers; sharing `.agents` does not mean every file is automatically loaded as a Skill.

If `worktree/.agents` is already a symlink whose lexical target is exactly the canonical source, preparation is idempotent. An existing real directory (including tracked content), file, wrong-target link, or broken link is a conflict. herdr-projects does not overwrite, remove, merge, or automatically migrate it. Failure is recorded before agent start, and no partial link is left behind. An older per-Skill layout is a real-directory conflict by design; it needs deliberate migration first.

For a manual migration, do not act while an agent is running. Inspect `git status --short` and `git ls-files -- .agents`, then inventory local-only files and the old per-Skill links. Back up the whole worktree `.agents` directory under a unique sibling name, preserving symlinks as symlinks and without dereferencing them. Keep tracked files and local-only contents available for deliberate review; do not merge them into the primary source blindly. Only after the backup and ownership of each item are verified, move the old directory aside (never delete it) and explicitly restart the thread. If anything is uncertain or tracked content cannot be preserved safely, leave the conflict in place and stop. Never remove or move the primary checkout's `.agents` source as part of this migration.

The preparation is synchronous behind the persisted launch barrier. A preparation error leaves the thread failed with its error recorded and can be retried. Restart waits for the old agent to exit and refuses a still-running agent; it does not retroactively change existing worktrees or sessions natively resumed by Herdr. This applies to local worktree threads, not tab, checkout, adopted, or remote worktrees. No global Git settings, ignore files, trust settings, permissions, or source contents are changed.

The source and destination are ordinary symbolic links, not copies. Git may report or ignore the worktree link according to machine-local ignore settings; herdr-projects does not stage it or change ignore rules. The link is enabled by the installed CLI for newly placed local worktree threads. To apply it to an existing worktree, first resolve any `.agents` conflict with the safe manual process above, ensure its agent has exited, then explicitly restart that thread (for example, `hp restart` where that command is linked). Herdr native resume does not rerun preparation. No Herdr restart is required. A later start/restart action may refresh a version-mismatched ticker and could schedule other pending agents; do not confuse that with retroactive changes to existing sessions.
